Введение: Что такое Spring?

Краткая история и назначение

Spring — это мощный фреймворк для разработки Java-приложений, созданный в 2003 году. Он упрощает разработку enterprise-приложений, предоставляя готовые решения для типичных задач.

Инверсия управления (IoC)

IoC — это принцип, при котором управление объектами передается фреймворку, а не программисту. Вместо того чтобы создавать объекты вручную, вы описываете, какие объекты нужны, и Spring сам создает и управляет ими.

Пример: вместо new UserService() Spring сам создаст и предоставит объект.

Внедрение зависимостей (DI)

DI — это способ реализации IoC, при котором зависимости (объекты, от которых зависит класс) автоматически "внедряются" в класс.

Пример: если UserController зависит от UserService, Spring сам подставит нужный объект.

Ключевые термины

  • IoC-контейнер — "сердце" Spring, который управляет жизненным циклом объектов
  • Bean — объект, созданный и управляемый Spring-контейнером
  • ApplicationContext — интерфейс, представляющий контекст приложения и контейнер бинов

Основы Spring MVC

Что такое MVC?

MVC (Model-View-Controller) — архитектурный паттерн, который разделяет приложение на три компонента:

  • Model — данные и бизнес-логика
  • View — представление (интерфейс пользователя)
  • Controller — обработчик запросов, связующее звено между Model и View

Роли компонентов

  • Model: хранит данные, которые нужно отобразить (например, список пользователей)
  • View: отображает данные пользователю (HTML-страница, шаблон)
  • Controller: получает HTTP-запрос, обрабатывает его, получает данные из Model и передает их View

Зачем использовать Spring MVC?

  • Четкое разделение ответственности
  • Упрощенная разработка веб-приложений
  • Гибкость и расширяемость
  • Отличная интеграция с другими компонентами Spring
  • Простота тестирования отдельных компонентов

Архитектура и поток запросов

DispatcherServlet

DispatcherServlet — центральный компонент Spring MVC, который является "фасадом" для всей обработки запросов.

Он получает все входящие HTTP-запросы и распределяет их по соответствующим компонентам.

Путь HTTP-запроса

  1. Пользователь отправляет HTTP-запрос (например, GET /users)
  2. Запрос попадает в DispatcherServlet
  3. DispatcherServlet определяет, какой HandlerMapping подходит для этого URL
  4. Находит соответствующий Controller и метод
  5. Вызывает метод контроллера, передавая параметры
  6. Контроллер обрабатывает запрос и возвращает имя представления (view name)
  7. DispatcherServlet передает результат ViewResolver
  8. ViewResolver находит нужный шаблон (например, HTML-файл)
  9. View отображает данные и возвращает HTML-ответ пользователю

Ключевые компоненты

  • HandlerMapping — определяет, какой контроллер обработает запрос
  • Controller — обрабатывает запрос и возвращает результат
  • ModelAndView — содержит данные (Model) и имя представления (View)
  • ViewResolver — преобразует имя представления в фактический View
  • View — отображает данные пользователю

Ключевые компоненты и аннотации

Контроллеры: @Controller и @RequestMapping

@Controller
public class HomeController {
    
    @RequestMapping("/") // Обработка запросов к корню
    public String home() {
        return "home"; // Имя шаблона (home.html)
    }
}

@Controller — помечает класс как компонент Spring MVC, который обрабатывает HTTP-запросы.

@RequestMapping — указывает, какой URL должен обрабатываться методом.

HTTP-методы: @GetMapping, @PostMapping

@Controller
public class UserController {
    
    @GetMapping("/users")
    public String getUsers(Model model) {
        // Получить список пользователей
        model.addAttribute("users", userService.getAllUsers());
        return "users";
    }
    
    @PostMapping("/users")
    public String createUser(@RequestParam String name) {
        userService.createUser(name);
        return "redirect:/users";
    }
}

Специализированные аннотации для разных HTTP-методов:

  • @GetMapping — GET-запросы
  • @PostMapping — POST-запросы
  • @PutMapping — PUT-запросы
  • @DeleteMapping — DELETE-запросы

Передача данных: Model

@GetMapping("/profile")
public String profile(Model model) {
    User user = userService.getCurrentUser();
    model.addAttribute("user", user);
    model.addAttribute("title", "Профиль пользователя");
    return "profile";
}

Model — это контейнер для данных, которые нужно передать в представление.

В шаблоне (например, Thymeleaf) данные доступны по именам атрибутов.

Представления: ViewResolver и шаблонизаторы

ViewResolver — компонент, который преобразует логическое имя представления (например, "home") в фактический ресурс (например, home.html).

Популярные шаблонизаторы:

  • Thymeleaf — современный шаблонизатор для HTML
  • JSP — классический подход (Java Server Pages)
  • Freemarker, Velocity — альтернативные шаблонизаторы

Простой пример (мини-приложение)

Шаг 1: Создание контроллера

@Controller
public class HelloController {
    
    @GetMapping("/")
    public String index(Model model) {
        model.addAttribute("message", "Добро пожаловать в Spring MVC!");
        model.addAttribute("currentTime", new Date());
        return "index";
    }
    
    @GetMapping("/hello/{name}")
    public String hello(@PathVariable String name, Model model) {
        model.addAttribute("name", name);
        return "hello";
    }
}

Шаг 2: Создание шаблонов (Thymeleaf)

resources/templates/index.html

<!DOCTYPE html>
<html xmlns:th="http://www.thymeleaf.org">
<head>
    <title>Главная</title>
</head>
<body>
    <h1 th:text="${message}"></h1>
    <p>Текущее время: <span th:text="${currentTime}"></span></p>
    <a href="/hello/World">Поприветствовать World</a>
</body>
</html>

Шаг 3: Конфигурация (application.properties)

# Настройка Thymeleaf
spring.thymeleaf.prefix=classpath:/templates/
spring.thymeleaf.suffix=.html
spring.thymeleaf.mode=HTML

# Настройка логирования
logging.level.org.springframework=INFO

Как это работает?

  1. Пользователь заходит на http://localhost:8080/
  2. DispatcherServlet направляет запрос методу index()
  3. Метод добавляет данные в Model и возвращает имя шаблона "index"
  4. ViewResolver находит файл index.html в папке templates
  5. Thymeleaf обрабатывает шаблон, подставляя значения из Model
  6. Пользователь видит готовую HTML-страницу

Заключение

Основные преимущества Spring MVC

  • Модульность — четкое разделение компонентов (MVC)
  • Гибкость — легко настраивается и расширяется
  • Простота тестирования — контроллеры можно тестировать как обычные классы
  • Богатая экосистема — интеграция с другими модулями Spring (Security, Data, Boot)
  • Поддержка современных практик — REST, WebSocket, реактивность

Краткое резюме

  • Spring — мощный фреймворк для Java-приложений с IoC и DI
  • Spring MVC — модуль для веб-разработки на основе паттерна MVC
  • DispatcherServlet — центральный компонент, управляющий потоком запросов
  • Аннотации (@Controller, @GetMapping) упрощают разработку
  • Model передает данные от контроллера к представлению
  • ViewResolver и шаблонизаторы (Thymeleaf) отображают данные пользователю

Совет: Начните с простых примеров и постепенно изучайте более сложные возможности Spring MVC. Практика — ключ к успеху!
