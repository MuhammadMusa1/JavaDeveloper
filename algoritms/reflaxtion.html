Введение

Что такое рефлексия?

Рефлексия — это механизм, позволяющий программе анализировать и изменять свою структуру и поведение во время выполнения.

Зачем нужна рефлексия?

  • Фреймворки (Spring, Hibernate) используют рефлексию для внедрения зависимостей и маппинга объектов
  • Тестовые фреймворки (JUnit) находят и запускают тесты по аннотациям
  • Инструменты для сериализации (Gson, Jackson)
  • Динамическая инспекция классов и объектов

Основные классы и интерфейсы

  • Class<T> — метаинформация о классе
  • Field — представляет поле класса
  • Method — представляет метод класса
  • Constructor — представляет конструктор класса

Основные операции

Получение объекта Class

// Способ 1: через .class
Class<String> stringClass = String.class;

// Способ 2: через объект
String str = "hello";
Class<?> cls = str.getClass();

// Способ 3: через имя класса (динамически)
try {
    Class<?> clazz = Class.forName("java.util.ArrayList");
} catch (ClassNotFoundException e) {
    e.printStackTrace();
}

Работа с полями

Field[] fields = MyClass.class.getDeclaredFields();
for (Field field : fields) {
    System.out.println("Поле: " + field.getName());
    field.setAccessible(true); // для доступа к private
    Object value = field.get(instance);
    field.set(instance, newValue);
}

Работа с методами

Method[] methods = MyClass.class.getDeclaredMethods();
for (Method method : methods) {
    System.out.println("Метод: " + method.getName());
    if (method.getName().equals("myMethod")) {
        method.setAccessible(true); // для private
        Object result = method.invoke(instance, args);
    }
}

Работа с конструкторами

Constructor<?>[] constructors = MyClass.class.getConstructors();
Constructor<?> constructor = MyClass.class.getConstructor(String.class);
MyClass instance = (MyClass) constructor.newInstance("arg");

Применение на практике

Пример 1: Инспекция класса

public static void printClassInfo(Class<?> clazz) {
    System.out.println("Класс: " + clazz.getName());
    
    System.out.println("Поля:");
    for (Field field : clazz.getDeclaredFields()) {
        System.out.println("  " + field.getType().getSimpleName() + " " + field.getName());
    }
    
    System.out.println("Методы:");
    for (Method method : clazz.getDeclaredMethods()) {
        System.out.println("  " + method.getReturnType().getSimpleName() + " " + method.getName());
    }
}

// Использование
printClassInfo(String.class);

Пример 2: Простой тестовый фреймворк

// Аннотация
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface Test {}

// Тестовый класс
public class MyTest {
    @Test
    public void testAddition() {
        assert 2 + 2 == 4;
        System.out.println("Тест прошёл!");
    }
}

// Запуск тестов
public static void runTests(Object testInstance) throws Exception {
    Method[] methods = testInstance.getClass().getDeclaredMethods();
    for (Method method : methods) {
        if (method.isAnnotationPresent(Test.class)) {
            System.out.println("Запуск теста: " + method.getName());
            method.setAccessible(true);
            method.invoke(testInstance);
        }
    }
}

Ограничения и риски

Производительность

Рефлексия значительно медленнее обычного вызова:

  • Нет оптимизации со стороны JVM
  • Проверки безопасности при каждом вызове
  • Пример: вызов метода через рефлексию может быть в 10-100 раз медленнее

Безопасность

Рефлексия может нарушить инкапсуляцию:

  • setAccessible(true) позволяет читать/менять private поля
  • Это может привести к неожиданному поведению и уязвимостям
  • Может обойти проверки безопасности (SecurityManager)

Читаемость и поддержка

  • Код становится менее понятным
  • Сложнее отлаживать
  • IDE не может помочь с автодополнением и проверкой типов
  • Ошибки выявляются только во время выполнения

Заключение

Резюме

Рефлексия — мощный инструмент, позволяющий работать с классами и объектами динамически.

Когда использовать

  • Создание фреймворков и библиотек
  • Сериализация/десериализация объектов
  • Тестирование (поиск и запуск тестов)
  • DI-контейнеры (внедрение зависимостей)
  • Инструменты анализа кода

Когда избегать

  • Обычное бизнес-приложение
  • Критичные по производительности участки кода
  • Если можно использовать обычные вызовы методов
  • Если есть альтернативы (интерфейсы, абстрактные классы)

Совет: Рефлексия — это инструмент для специальных случаев, а не для повседневного программирования.
